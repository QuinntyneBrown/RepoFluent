The curriculum contract

The contract is the agreement between whatever produces a curriculum package and RepoFluent, which consumes it. It is published as a versioned, checksummed release you can download and verify — not as documentation you have to trust.

Finding the page

This page has no navigation link

Add /contracts to your instance address. It works for anyone, with no persona required — the contract is public information. Bookmark it if you author content.

While the page is loading it says it is verifying. That is literal: the instance recomputes the checksum of every artifact and the aggregate release checksum on every request, rather than reading a stored value. If it reports Contract release unavailable, the release failed its own verification and that is an instance problem worth reporting.

The release and its checksum

One contract release exists today: 0.1.0, published as a prerelease. The page shows its verification state and a release checksum over the whole release.

Under Checksummed artifacts, each file is listed as a card with a download link and its own hash. The set is fixed for the release; nothing can be added, removed, or edited after publication.

Fetching artifacts directly

Both the manifest and each artifact are retrievable over plain HTTP, which is what lets a build pipeline pull the schema and verify it. Requesting a version that does not exist returns CIC_CONTRACT_VERSION_UNSUPPORTED; requesting a path the release does not declare returns CIC_CONTRACT_ARTIFACT_NOT_FOUND; a path that tries to escape the release returns CIC_CONTRACT_ARTIFACT_PATH.

Retrieving the manifest

/api/contracts/curriculum/releases/0.1.0

and, for a single file, /api/contracts/curriculum/releases/0.1.0/artifacts/curriculum.schema.json

Relative to your instance address. Always verify the hash you get against the one in the manifest — that is what the checksums are for.

Compatibility and migration policy

The point of the policy is that you are not locked into one agent, model, or generation workflow, and that an upgrade cannot silently change what your existing packages mean.

What a version change signifies

Major
Breaking changes to package shape or meaning that require an explicit migration.
Minor
Backward-compatible additions that an older consumer may safely ignore.
Patch
Clarifications, fixture corrections, and validation fixes that do not change accepted semantics.

The supported version window

Today: >=0.1.0 <0.2.0. A package declaring a contract version outside the window is rejected with CIC_UNSUPPORTED_VERSION, and the rejection identifies the supported line rather than failing vaguely.

Backward compatible
A 0.1.x consumer accepts packages produced for 0.1.0 where required semantics are unchanged.
Forward compatible
A 0.1.0 consumer rejects unknown required semantics and ignores only declared optional extensions. That asymmetry is deliberate: silently ignoring something a package said was required would be unsafe.
Deprecation notice
180 days before a supported version is withdrawn.
Migration responsibility
Contract maintainers, not you.
A migration preserves
Stable identifiers and protected semantics.
If something cannot be preserved
You get an explicit loss report, addressed by path, before publication — never a silent drop.

The conformance suite

The page ends with Conformance fixture suite: the total number of cases, how many are expected to succeed, how many are expected to fail, and the categories covered. Today that is ten cases — two that must validate and eight that must be rejected in a specific way.

Testing the failures is the more valuable half. It is easy to write a validator that accepts good packages; the suite proves this one rejects bad ones for the right reason, at the right path, with the right code.

Why this matters if you are building an authoring pipeline

Because the codes, the schema, and the failure cases are all published and checksummed, you can hold your own generator to exactly the same standard the server applies — before anything is uploaded. That is what the authoring kit automates.
