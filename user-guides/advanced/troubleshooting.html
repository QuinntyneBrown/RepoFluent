Troubleshooting

Start from what you see. Almost every problem in RepoFluent is one of three things: you are the wrong persona, the curriculum is in the wrong state, or something is genuinely not implemented. This page sorts them out.

  • All roles
RF-UG-21

Check these three things first

  1. Which persona are you?

    Look at the menu in the header. This explains most missing buttons and most refused actions, and switching takes a second. See Roles and permissions.

  2. What state is the curriculum in?

    Read the status pill in panel 02. Publishing needs Approved, not Ready for review. See Lifecycle and evidence.

  3. Have you reloaded?

    If somebody else advanced the curriculum while your page was open, your page is stale and RepoFluent will refuse actions on purpose rather than let you act on what you last saw.

Access and identity

Symptom Cause Fix
Nothing loads; every panel says unavailable The application is running but the API is not reachable. Report the address to whoever operates the instance. There is nothing to fix from your side.
Requests are refused as unauthenticated No persona is being sent, or the persona is not recognized. Re-pick a persona from the header menu. If that fails, clear site data for the instance and reload.
Everything is refused and the persona menu has no effect The instance is not running in a development, test, or acceptance-test configuration, so personas are disabled entirely. Nothing you can do. This is a deliberate safeguard so test identities never reach a real deployment.
Learning dashboard unavailable You are on the Learning page as Author, Reviewer, Administrator, or Auditor. Switch to the Learner persona.
A colleague sees different buttons Different persona, or a different point in the lifecycle. Compare both. Persona is per browser, so two people on the same instance genuinely can be different roles.

Uploading

Symptom Cause Fix
Choose a curriculum package first You pressed upload without selecting a file. Select the JSON file, then upload.
Refused for media type, size, or unsafe content Wrong kind of file, empty, over 512 KiB, or not strict UTF-8 JSON. See Intake refusals.
CLI_PACKAGE_VERSION_CONFLICT This identity and version already exist with different bytes. Increment the declared version in the package and upload again.
CLI_INTAKE_RETRY Two identical uploads collided. Wait a moment and upload again.
Badged Existing receipt when you expected a new draft Not a fault. Your bytes are identical to an existing upload, so the existing draft was reused. If you meant to change something, check you exported the file you edited.
Stuck on Validating or CLI_VALIDATION_STALE Validation has been running over five minutes. Usually the background worker is not running. Press Retry validation. If it stalls again, quote the correlation identifier to an operator.
Awaiting worker that never clears The package was accepted but nothing has picked it up. Same as above — this is an instance problem, not a content problem.
CLI_RETRY_NOT_ACTIONABLE You tried to retry something that is not a stale validation. Retry only applies while the state is Validating and it has gone stale.
CLI_IMPORT_NOT_FOUND The import your browser remembered no longer exists — commonly after the instance database was reset. Upload again.

Review, publication, and retirement

These refusals almost always mean the lifecycle moved, or a gate is open. They are guards, not faults.

Code Means Fix
CLI_STALE_CHECKSUM The package is not the one your page was showing. Reload and read the evidence again before deciding. Do not retry blind.
CLI_STALE_VALIDATION_REPORT The validation report changed under you. Reload; the issue set may now be different.
CLI_STALE_WARNING_REPORT The warnings you were about to acknowledge are no longer the current set. Reload and acknowledge the current set.
CLI_WARNING_ACKNOWLEDGEMENT_REQUIRED You tried to approve with a warning outstanding. Press Acknowledge exact warnings first.
CLI_WARNING_ACKNOWLEDGEMENT_GATE You tried to acknowledge when there is nothing to acknowledge, or errors exist. Acknowledgement needs zero errors and at least one warning.
CLI_REVIEW_RATIONALE_REQUIRED A rejection without an explanation. Type a rationale; the button unlocks.
CLI_REVIEW_DECISION_IMMUTABLE A decision already exists for this version and cannot be changed. A new version is the only way forward. This is by design.
CLI_REVIEW_REJECTED This version was refused by a reviewer. The author produces a new version.
CLI_PUBLICATION_REVIEW_REQUIRED Publishing something with no matching approval. It must be approved first, at this exact checksum.
CLI_PUBLICATION_CHANGED or CLI_PUBLICATION_CONFLICT The publication state moved while you were acting, or two publications collided. Reload. If a version already exists, publishing again is unnecessary.
CLI_RETIREMENT_REASON_REQUIRED The retirement reason box is empty. Write why, naming the successor if there is one.
CLI_RETIREMENT_PUBLICATION_REQUIRED There is nothing published to retire. Publish first.
CLI_INVALID_TRANSITION The action does not exist for the current state. Read the status pill. The lifecycle only moves forward.
CLI_PREVIEW_GATE Preview is only available for a draft or an approved version. Check the state; a published version is read as learning, not previewed.

Comparison and assignment

Code or symptom Means Fix
CLI_COMPARISON_BASE_NOT_FOUND The base identifier does not name a retained published version. Check for a copy-paste error. There is no picker, so this is usually a typo.
CLI_COMPARISON_PACKAGE_MISMATCH The two versions are different curricula. Compare within one package identity only.
CLI_COMPARISON_DISTINCT_VERSIONS_REQUIRED You gave the same version twice. Use two different versions.
CLI_COMPARISON_TARGET_REQUIRED No target version was identified. Run the comparison from the newer published version's own panel.
Assignment refused as not found The version has been retired. Publish a current version and assign that. Retired versions accept no new assignments — see Retiring a version.
The learner menu is empty or has one option One learner exists in this release. Not a fault. Assign to Maya Quinn.

Learning

Symptom Cause and fix
No learning assigned You are a learner and nothing has been assigned. An administrator must publish a version and assign it.
Course unavailable The course is not assigned to you, or the address is wrong. Go back to My learning and use Start course.
Unsupported lesson block with LEX-BLOCK-UNSUPPORTED The package used a block type this version cannot render. The rest of the lesson is fine. Report the code and the lesson title.
Progress never moves off zero Expected. Progress is not tracked in this release; every figure is a placeholder. See About the progress figures.
Find-in-page cannot find text you know is in the lesson Long lessons reveal ten blocks at a time and hidden blocks are genuinely absent from the page. Press Show more lesson blocks until everything is revealed.
The code excerpt looks out of date It is bound to the commit shown, which is correct behavior. Check the branch and commit in the panel, then look at the current file in your own tools.

Display and browser

Symptom Cause and fix
Browser compatibility mode notice A required capability is missing. Content stays available with effects reduced. Use a current Chrome, Edge, Firefox, or Safari — see Before you begin.
The system map is a table rather than a graphic Graphics acceleration is unavailable, disabled, or failed to start. The semantic view is a full equivalent, not a degraded one.
The sidebar disappeared Your window or zoom level crossed a layout breakpoint. Expected.
Nothing animates Reduced motion is on, in your system or browser. State changes still happen immediately.
Ctrl K search returns nothing Expected. The dialog exists; the search behind it does not. There is no search in this release.
A control does nothing when pressed Check it is not one of the known inert controls: the lesson Rendered/Source toggle, the workspace explorer tree, the tab and breadcrumb strip, the sync pill, or Open related learning on the system map. See What is scenery.

Still stuck

Collect the correlation identifier and the stable code, then report the problem without sending your curriculum. What to include, and why content is never necessary, is on Audit and support.
