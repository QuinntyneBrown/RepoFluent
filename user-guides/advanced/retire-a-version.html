Retiring a version

Retirement withdraws a version from future use without deleting it or disrupting anyone currently using it. It is the correct answer when content has gone stale, and it is deliberately not a delete.

  • Administrator
RF-UG-17

Exactly what retirement does

Retirement sets a version's availability to continue access. Three things follow, and the panel states all three back to you.

No new assignment Existing assignments continue Historical content retained
After retirement Result
Assigning it to somebody new refused Not found. This is the intended effect.
A learner who already has it opening a lesson works Unchanged. Nobody is interrupted mid-course.
The content itself retained Still resolvable, still immutable. Nothing is deleted.
Comparing it with another version works Retired versions remain comparable.
The lifecycle history retained Complete and permanent, with the retirement added to it.
Retirement is not deletion, and there is no deletion

Nothing in this release removes curriculum content or learning records. That is deliberate: a learning record has to keep pointing at retrievable content to mean anything. Retention and deletion workflows are a design intention, not a present capability.

When to retire

GOOD REASONS retire
  • A newer version is published and comparison shows real change — retire the old one so it stops being assigned.
  • The system it describes has been restructured and the content is now misleading.
  • The source repository has moved or been archived, so the code references no longer help.
  • A defect was found in the content that cannot be corrected in place, because published versions are immutable.
NOT REASONS do not
  • To tidy up. Retirement is permanent and appears in the audit trail forever.
  • To stop one person seeing something. There is no per-learner withdrawal, and retirement does not remove existing access.
  • To fix a typo. Publish a corrected version instead; the old one can simply stop being assigned.
  • Before the replacement exists. Retire after the new version is published, not before.

Retiring

As an administrator, with a published curriculum open, find Retire published version.

  1. Write a retirement reason

    Required. The Retire version button stays disabled until the box has content. The reason is stored permanently with the retirement and is the first thing anybody reading the history later will look for, so write for that reader.

    A good reason names the successor Superseded by version 2.0.0 after the order intake boundary moved to the workflow service; source references in three lessons no longer resolve.
  2. Press Retire version
    What you should see The status pill changes to Retired, and a Retirement evidence block appears with the three guarantees, who retired it, the reason, the version identity, and the retirement event identifier.
  3. Tell the people affected

    RepoFluent sends no notifications. Anyone holding an assignment for the retired version keeps working through content you have just declared stale, and will not know unless you tell them.

Retiring twice is harmless — the second attempt returns the existing retirement rather than recording another.

When retirement is refused

  • No retirement form. You are not an administrator, or the curriculum is not published.
  • Reason required. The box is empty.
  • Publication required. There is nothing published to retire.

After retiring

The Availability policy line in the publication evidence changes from Active for assignment to reflect retained history. That line is the quickest way to check whether a version is still assignable.

A sensible sequence for replacing stale content end to end:

  1. The author regenerates and publishes the new version.
  2. Compare the two and record what changed — see Comparing versions.
  3. Assign the new version to everyone who needs it.
  4. Retire the old version, naming the successor in the reason.
  5. Tell the affected learners, since the product will not.

Retirement is fully visible to an auditor as a Retired entry with its actor, timestamp, and correlation identifier — see Audit and support.
