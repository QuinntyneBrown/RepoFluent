Your first curriculum

Because you control every persona, you can drive the entire product single-handedly. In about fifteen minutes you will take a JSON file, get it validated, review and approve it, publish it, assign it to a learner, and then read the resulting lesson and the source code behind it. Do this once and the rest of the guide will make sense.

  • Everyone
  • ~15 minutes
RF-UG-05

Before you start

You need a curriculum package to upload. Your instance ships with a worked example of a C# and Angular order-processing system, which is the file this walkthrough uses:

The example package
contracts/curriculum/0.1.0/fixtures/order-processing.json

That path is relative to the root of the RepoFluent repository. If you do not have a copy of the repository, ask whoever runs your instance for the file, or download examples/valid/order-processing.json from the authoring kit page in the application — it is the same content.

Open your instance and confirm you can see the heading Curriculum imports. If you can, you are ready.

Part one — upload and validate

  1. Become the authorPersona: Author

    Set the Development persona menu in the header to Author. Only an author can upload.

  2. Choose the file

    In panel 01 find the field labelled Curriculum package and select order-processing.json.

    What you should see The live status line changes from Ready for a curriculum package to Curriculum package selected.
  3. Press Upload and validate

    RepoFluent accepts the file and hands you a receipt immediately; validation then happens in the background. You will see the status move through Uploading curriculum package and Validating curriculum package on its own — do not press anything again.

    What you should see Within a second or two, the status reads Curriculum package is ready for review and a status pill labelled Ready for review appears in panel 02.
  4. Look at the evidence you just created

    Panel 02 now shows a Content checksum beginning sha256:, a Correlation identifier, the package identity and version, and a Validation evidence block reading 0 errors · 1 warning across eleven check categories.

    That single warning is deliberate. The example package declares a contract extension RepoFluent does not implement, which is non-blocking — the core content is interpreted normally. You will clear it in part two.

The checksum is the point

Every later decision is bound to this exact checksum. If the bytes change, approvals and warning acknowledgements stop being valid and have to be made again. This is what stops content from being swapped after review.

Full detail on this stage: Uploading a package.

Part two — review and approve

  1. Become the reviewerPersona: Reviewer

    Switch the persona menu to Reviewer. The page reloads its data and a different set of buttons appears.

  2. Press Preview draft

    This renders the draft through the same renderer a learner uses, with three safeguards active: no learner progress is written, no assessment state is written, and correct answers are withheld from the response entirely.

    What you should see A Draft preview section containing the lesson How an order becomes a workflow.
  3. Acknowledge the warning

    Press Acknowledge exact warnings. You cannot approve while an unacknowledged warning exists, and the acknowledgement is bound to this precise set of issues — not to "warnings in general".

    What you should see The warning gate flips from Acknowledgement required to Warnings acknowledged.
  4. Optionally record your rationale

    The Review rationale box is where you write what you actually checked. It is optional for an approval and required for a rejection — the reject button stays disabled until you type something.

  5. Press Approve this checksum

    Note the wording. You are not approving "the curriculum", you are approving one immutable set of bytes.

    What you should see A Review decision evidence region showing Approved, who approved it, the package checksum, the validation-report checksum, and your rationale.
There is no undo

A review decision is recorded once and can never be edited or replaced. If you reject this draft you cannot then approve it — the author has to produce a new version. Read the whole panel before you press either button.

Full detail on this stage: Reviewing a draft.

Part three — publish and assign

  1. Become the administratorPersona: Administrator

    Switch the persona menu to Administrator.

  2. Press Publish version

    Publication creates one immutable published version bound to the exact checksum the reviewer approved.

    What you should see The status pill reads Published and a Publication evidence block appears with an Active for assignment pill, the version identity, who published it, and four immutability guarantees.
  3. Assign it to the learner

    Scroll to Assign published learning. Choose Maya Quinn · Learner — the only learner that exists — tick Required assignment, and press Assign learner.

    What you should see The status region reads Assignment created.

Full detail on this stage: Publishing and assigning.

Part four — learn it

  1. Become the learnerPersona: Learner

    Switch the persona menu to Learner, then choose Learning in the activity bar on the left.

    What you should see The My learning page greeting Maya, with one assignment card for Order Processing Foundations marked Required.
  2. Press Start course

    The course page shows its outcomes, difficulty, estimated minutes, and a Course outline of modules and numbered lessons.

  3. Open the lesson

    Choose How an order becomes a workflow. You are now reading generated learning content that is bound to a specific commit of a real repository.

  4. Open the code behind the explanation

    Find the code reference block and press Open source context for OrderController.Create.

    What you should see A Source context panel — beside the lesson on a wide screen, as a drawer on a narrow one — showing src/Order.Api/Controllers/OrderController.cs, the branch and commit it came from, the line range, and a Provenance · verified note. Your place in the lesson is preserved, and the browser Back button closes the panel.
That is the product

You have taken agent-generated content through validation, human approval, immutable publication, and assignment, and then read it as a learner with the source code one press away and its provenance intact.

Three things worth trying next

Upload the same file again
As Author, upload order-processing.json a second time. RepoFluent recognizes the identical bytes, reuses the existing draft, and labels the receipt Existing receipt rather than creating a duplicate. See Uploading a package.
Look at the history
Switch to Auditor and press Inspect lifecycle history. Every step you just took is there in order, with the actor, state, timestamp, and correlation identifier. See Audit and support.
Break something on purpose
Try uploading a file that is not JSON, or an edited copy of the example with the same version but different content. Both are refused, with a specific code and an exact location. See Validation issues.
