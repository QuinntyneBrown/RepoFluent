Before you begin

RepoFluent runs entirely in your browser. There is nothing to install, nothing to configure, and no account to create. You need three things: a supported browser, the address of a RepoFluent instance, and — if you are going to upload content — a curriculum package to upload.

  • Everyone
RF-UG-02

What you need

An address to open
RepoFluent is a web application served from a URL. Somebody on your team runs the instance; ask them for the address. There is no public, hosted RepoFluent service, so if nobody has told you a URL, nobody has started one yet.
A supported browser
A current release of Chrome, Edge, Firefox, or Safari. See Supported browsers below.
No credentials
This release has no sign-in form, no password, and no single sign-on. You pick an identity from a menu in the header. This is explained in full on Opening RepoFluent.
A curriculum package, if you author
A single JSON file, at most 512 KiB, produced by an authoring agent and validated offline before you upload it. See The authoring kit. If you only want to try the product, your instance ships with a worked example described in Your first curriculum.
If the address does not load at all

RepoFluent is two parts — an application and an API — and both have to be running. A page that loads but shows unavailable messages everywhere usually means the API is not up. Report the address you tried to whoever operates the instance rather than trying to diagnose it yourself.

Supported browsers

RepoFluent follows the Angular 21 widely available Baseline, with a baseline date of 20 October 2025. In practice that means any browser release that is current or near-current is supported. The instance publishes its own policy — you can read it yourself at any time on the Quality page inside the application.

Capabilities RepoFluent requires

Five browser capabilities are mandatory. Every supported browser above has had them for years; they are listed because RepoFluent checks for them and changes its behavior if one is missing.

  • Native dialog — modal windows.
  • CSS Grid — the whole page layout.
  • Custom events — internal communication.
  • Abort controller — cancelling requests.
  • Animation frames — smooth reveal and scrolling.

What happens on an unsupported browser

RepoFluent does not lock you out. If a required capability is missing you get a Browser compatibility mode notice near the top of the page reading Effects reduced · safe access active, visual effects are switched off, and the content stays readable and operable. The notice deliberately does not name the browser or version, so it never leaks information about your environment.

Nothing important depends on graphics acceleration

WebGPU is optional. RepoFluent uses it only to make the system map look better. If your machine or browser has no WebGPU, or it fails to start, the map falls back to a semantic view with the same information in a table you can read and operate by keyboard. No lesson, assessment, control, or status is ever available only through a graphical effect.

Screens, zoom, and motion

RepoFluent is designed for desktop and tablet, and the lesson and review flows stay usable on a narrow phone-sized window. Nothing scrolls sideways: if a table or code excerpt is wider than your screen, that one element scrolls inside its own frame while the page itself does not.

Width What changes
Wide desktop Full frame. Source code opens beside the lesson as a split view so you can read both at once.
Narrow desktop or tablet The workspace sidebar is hidden to give content more room.
Phone-sized window Navigation moves to the bottom of the screen, the status bar is hidden, and source code opens as a drawer over the lesson instead of beside it.

Zoom

Interactive controls stay visible and operable at high browser zoom. Zooming to 200% is equivalent to halving the window width, so at high zoom on a normal monitor you will see the narrow layout described above. That is expected, not a fault.

Reduced motion

If your operating system or browser is set to reduce motion, RepoFluent honors it automatically: animations are reduced to effectively nothing while every state change still happens immediately. You never have to wait out an animation to see a result, and reducing motion never hides information. See Accessibility and preferences.

How fast it should feel

The instance publishes the performance targets it is measured against, so you can tell the difference between "this product is slow" and "something is wrong right now". You can read the current figures on the Quality page in the application.

Shell ready
Within 2.5 seconds, measured as the main heading being visible and navigation being operable.
Typical interaction
Under 200 milliseconds.
Animation
60 frames per second, degrading rather than stuttering.
Reference conditions
Desktop with 4 logical cores and 8 GB memory, Chromium stable, 10 Mbps broadband at 40 ms round trip, cold shell and warm interaction, over a lesson of 33 blocks.

If your experience is much worse than this and your machine and connection are comparable, that is worth reporting. See Troubleshooting for what information to include.
