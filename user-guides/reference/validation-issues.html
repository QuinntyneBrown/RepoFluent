Validation issues

Every rejection RepoFluent issues carries a stable code, a severity, and the exact location in your package that caused it. This page explains how to read that, and lists every code with what to do about it.

  • Author
  • Reviewer
RF-UG-12

Two families of problem

Codes beginning CLI_ and codes beginning CIC_ mean quite different things, and knowing which you are looking at tells you immediately where to look for the cause.

CLI_ — INTAKE AND WORKFLOW no receipt

The file was refused before it was accepted, or an action was refused because of the lifecycle state. Nothing was recorded and no draft exists. The problem is with the file itself or with what you were trying to do — not with the content inside.

CIC_ — CONTRACT VALIDATION receipt exists

The file was accepted and validated against the curriculum contract. Every issue names an exact JSON path inside your package. This is where you spend most of your time.

Reading the issues table

Validation issues appear in a four-column table in panel 02 of the Curricula page.

Code
A stable identifier such as CIC_DUPLICATE_ID. Stable means it will not be reworded between releases, so it is safe to search for, script against, and quote in a bug report.
Severity
Either an error or a warning. See below.
JSON path
The precise location in your package. This is the single most useful column — go straight there rather than reading the whole file. RepoFluent reports every offending path, not just the first, so one pass through the table is enough.
Message
A human explanation of what the rule requires.

Errors block; warnings gate

Severity Effect Who clears it
Error No draft. The table is announced as an alert with the heading Blocking validation issues — Resolve each issue, regenerate the package, and validate again. There is no override. The author, by fixing the package and uploading a new version.
Warning A perfectly reviewable draft, but publication is gated. A typical example reads Noncritical extension ignored — Core interpretation is unchanged and the package remains reviewable. A reviewer, with Acknowledge exact warnings.

The issue-set checksum

The validation receipt includes a checksum over the exact set of issues found. A reviewer's warning acknowledgement is bound to it, so if the package is revalidated and the issue set changes at all, the acknowledgement is invalidated automatically. Nobody can acknowledge one set of warnings and publish a different set.

The eleven check categories

Every validation run applies the same eleven categories of check, and the receipt records that it did. Knowing them helps you predict what will be examined.

Intake refusals

These happen before a receipt exists. The upload did not take place, so there is nothing to fix in RepoFluent — fix the file and upload again. Every refusal is still recorded in the instance's audit history.

Code Cause What to do
CLI_FORM_REQUIRED The request carried no upload form at all. Use the Curriculum package field on the page rather than constructing a request by hand.
CLI_FILE_REQUIRED No file was attached. Choose a file before pressing upload.
CLI_UNSUPPORTED_MEDIA The file is not a .json file and was not sent as application/json. Upload the JSON package itself. Do not zip it, rename it, or wrap it in anything.
CLI_PACKAGE_LIMIT Empty, or larger than 512 KiB. Reduce the package. The usual cause is embedding long source excerpts; include only the lines the lesson needs.
CLI_UNSAFE_CONTENT The file begins like an executable, a zip archive, or a PDF, or contains null bytes. You have almost certainly picked the wrong file. Check what you selected.
CLI_MALFORMED_PACKAGE Not strict UTF-8 JSON with a single root object — or it uses comments, trailing commas, or nests deeper than 128 levels. Run the offline validator, which reports the same problem with a location.
CLI_PACKAGE_VERSION_CONFLICT This package identity and version already exist with different bytes. Increment the version in the package. This rule protects content that has already been reviewed.
CLI_INTAKE_RETRY Two identical uploads arrived at once and one lost the race. Wait a moment and upload again.

Codes for refused workflow actions — stale checksums, review gates, publication and retirement conflicts — are listed symptom-first on Troubleshooting.

Contract codes: security restrictions

These are the strictest rules in the contract, and none of them can be waived. RepoFluent will never render active content or reach out to an undeclared remote resource, because a curriculum package is untrusted input.

Code Meaning and remedy
CIC_ACTIVE_CONTENT A lesson block contains active HTML, script, executable, or macro content. Remove it. Lesson content is plain structured text; there is no way to embed behavior.
CIC_UNDECLARED_RESOURCE A lesson block refers to a remote resource that no approved extension declared. Remove the reference or supply the content inline.
CIC_FORBIDDEN_PATH A source path is absolute or escapes its repository root. Use repository-relative paths only — never a path from your own machine.
CIC_UNSUPPORTED_CLASSIFICATION A supplied source excerpt has no supported content classification. Every excerpt must declare what kind of content it is.
CIC_CONTRACT_ARTIFACT_PATH A requested contract artifact path escapes its release. This appears when retrieving release artifacts, not when validating a package.

Contract codes: assessment integrity

Assessments are validated even though this release cannot yet administer one. That is deliberate: the content is correct now, so it will work when the assessment interface arrives.

Code Meaning and remedy
CIC_ANSWER_NOT_PROTECTED An answer is not classified as protected. Answer keys must be marked so RepoFluent can keep them out of learner-visible and reviewer-visible responses.
CIC_UNSUPPORTED_ASSESSMENT The assessment purpose is not supported.
CIC_UNSUPPORTED_ITEM The item type is not supported. Use a question type with a deterministic grading method.
CIC_UNSUPPORTED_SELECTION The item selection mode is not supported.
CIC_INVALID_SELECTION Item selection is empty or out of range.
CIC_UNSUPPORTED_FEEDBACK_RELEASE The feedback-release policy is not supported. Formative and summative assessments release feedback differently.
CIC_INVALID_ATTEMPTS The maximum attempts value is out of range.
CIC_INVALID_POINTS A grading points value is out of range.
CIC_INVALID_THRESHOLD A passing threshold is not between 0 and 100 percent.

Contract codes: references and provenance

This group is the most common source of real errors, because it is where an agent's claims are checked against the sources it says it used. An error here usually means the content is describing something that is not actually there.

Code Meaning and remedy
CIC_DANGLING_CITATION A citation does not resolve to a declared repository document. Either declare the document in the source snapshot or remove the claim that depends on it.
CIC_DANGLING_REFERENCE A typed identifier points at nothing. Usually a lesson referring to an objective or assessment that was renamed or dropped.
CIC_DANGLING_RELATIONSHIP An architecture relationship names an endpoint that was never declared as a system or subsystem.
CIC_DANGLING_REPOSITORY A code reference points at a repository that the source snapshot does not declare.
CIC_REVISION_MISMATCH A code reference's branch or commit does not match its declared source snapshot. This is the guard that stops a lesson claiming to describe one revision while quoting another.
CIC_SOURCE_REVISION_REQUIRED A source repository has no revision, branch, or commit identity. Content without a revision cannot be checked for staleness later.
CIC_UNSUPPORTED_RELATIONSHIP The architecture relationship type is not supported.
CIC_UNSUPPORTED_EVIDENCE_TYPE A citation must declare whether it is direct evidence, synthesis, or interpretation. Being explicit about which is how a reviewer knows how hard to look.
CIC_UNSUPPORTED_CONFIDENCE Evidence confidence is not one of the supported explicit states. Uncertainty must be stated, not implied.

Contract codes: identifiers, ordering, and limits

Code Meaning and remedy
CIC_DUPLICATE_ID A stable identifier is used twice. RepoFluent reports every colliding path rather than overwriting one entity with another.
CIC_INVALID_ID An identifier is not normalized lowercase kebab case — for example order-processing-foundations.
CIC_INVALID_ORDER An ordering value is out of range.
CIC_INVALID_RANGE A source line range is invalid — for example an end line before its start line.
CIC_INVALID_DURATION A duration or time limit is out of range.

Contract codes: types, required fields, and formats

Most of these are caught by the offline validator in a second, which is why running it first is worth the trouble.

Code Meaning and remedy
CIC_REQUIRED A required contract value is absent.
CIC_EMPTY_PACKAGE The package has no content.
CIC_INVALID_JSON The content cannot be read as the versioned package contract. Structurally valid JSON that is not a curriculum package lands here.
CIC_NON_CANONICAL_DATE_TIME A date and time is not RFC 3339 UTC with a Z suffix. Local times and offsets are rejected so that timestamps compare correctly across versions.
CIC_UNSUPPORTED_BLOCK The lesson block type is not allow-listed. See the eight supported blocks.
CIC_UNSUPPORTED_CALLOUT The callout tone is not allow-listed.
CIC_UNSUPPORTED_LANGUAGE A code reference language is not allow-listed. C# and Angular are the supported ecosystems in this release.
CIC_UNSUPPORTED_DIFFICULTY The learning difficulty value is not supported.
CIC_UNSUPPORTED_LOCALE The package locale is outside the supported catalog.

Contract codes: extensions

Extensions let a package carry data the core contract does not define. The rule is simple: an extension may add, but it may never change how core content is interpreted.

Code Severity Meaning and remedy
CIC_EXTENSION_IGNORED warning An unsupported noncritical extension was ignored. Core interpretation is unchanged and the draft is reviewable. This is the warning the worked example package produces.
CIC_UNSUPPORTED_CRITICAL_EXTENSION error A critical extension is not supported. Marking an extension critical means "refuse rather than ignore me", so RepoFluent does. Either drop the extension or stop marking it critical.
CIC_EXTENSION_REDEFINES_CORE error An extension tried to redefine a core package field. Move the data into the extension's own namespace.
CIC_INVALID_EXTENSION_DATA error The payload is missing or is not a JSON object.
CIC_INVALID_EXTENSION_NAMESPACE error The namespace is not normalized reverse-domain notation, for example com.example.my-extension.
CIC_INVALID_EXTENSION_VERSION error The extension version is not a canonical semantic version.

Contract codes: compatibility and releases

Code Meaning and remedy
CIC_UNSUPPORTED_VERSION The package declares a contract version outside the supported window. Regenerate against a supported contract — see The curriculum contract.
CIC_CONTRACT_VERSION_UNSUPPORTED You asked the instance for a contract release it has not published. Only 0.1.0 exists today.
CIC_CONTRACT_ARTIFACT_NOT_FOUND The artifact you requested is not declared by that release.
CIC_CONTRACT_RELEASE_INVALID A published release failed its own checksum or manifest verification. This is an instance problem, not yours — report it with the correlation identifier.
The catalog is published, not just documented

This list mirrors validation-codes.json, which ships inside every contract release and inside the authoring kit. Your offline validator reports exactly the same codes the server does, so you can resolve everything on this page without uploading anything.
