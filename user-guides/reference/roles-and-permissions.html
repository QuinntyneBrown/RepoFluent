Roles and permissions

RepoFluent decides which controls to offer you from two facts: your persona, and the current lifecycle state. That is the entire model. If a button is not there, one of those two is the reason, and this page will tell you which.

Note the two surprises

A Reviewer cannot read the lifecycle history, and an Author does not get the Preview draft button — an author uses Inspect contract model instead, which shows the whole package rather than one rendered lesson. Both are deliberate.

By persona

The same information read the other way round, which is more useful when you are deciding which persona to switch to.

Author
Upload. Read import status, validation evidence, and lifecycle history. Inspect the contract model. Retry stale validation.
Cannot: acknowledge, approve, reject, publish, assign, retire, compare, or open the learner preview.
Reviewer
Read import status. Inspect the contract model. Preview as a learner. Acknowledge exact warnings. Approve or reject a checksum. Compare published versions.
Cannot: upload, publish, assign, retire, retry validation, or read the lifecycle history.
Administrator
Read import status and lifecycle history. Inspect the contract model. Publish. Assign. Retire. Compare. Retry stale validation.
Cannot: upload, acknowledge warnings, approve, or reject. Publication is deliberately separated from approval.
Auditor
Read import status and the complete lifecycle history. Nothing else at all — no preview, no contract model, no decisions, no publication, no assignment. This is a genuine read-only role, not a role with restrictions.
Learner
List your own assignments and open the courses, lessons, and source context they contain. Nothing on the Curricula page. You cannot see another learner's record, and there is no other learner to see.

Why a button is missing

Work down this list; the first match is almost always the answer.

  1. Check your persona

    Look at the menu in the header. Switching persona is instant and the page re-fetches, so this takes five seconds to rule out.

  2. Check the state

    Read the status pill in panel 02. Publishing needs Approved, not Ready for review. Comparing needs Published. Retrying needs a stale Validating.

  3. Check for a gate

    Approve this checksum is replaced by Acknowledge exact warnings while a warning is outstanding — the two are never both offered. Clear the gate and the approve button appears.

  4. Check whether it already happened

    Review decisions and publications are one-time. If the evidence block is already there, the action is done and the button is gone for good.

  5. Reload

    If somebody else advanced the curriculum while your page was open, your page is out of date. Reload before concluding anything is wrong.

How the rules are enforced

The buttons you see are computed by the server, not decided by the page. For each import, RepoFluent works out the list of actions your persona may take in the current state and sends that list to the page, which shows only those controls. Two consequences matter.

  • The interface cannot be tricked. Showing a hidden button would not help — the API applies the same rules and refuses.
  • Refusals are specific. A rejected action returns a stable code and a correlation identifier rather than a generic error, so you can tell a permission problem from a state problem. See Troubleshooting.
What this model does not do yet

Everything happens inside a single tenant with a single fixed set of five identities. There are no user accounts, no groups or teams, no way to grant one person two roles, no scoping of permissions to particular curricula or repositories, and no separation-of-duties rule stopping the same person from authoring and reviewing the same package. Those are design intentions, not present behavior.
