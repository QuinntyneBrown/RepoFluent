Accessibility and preferences

RepoFluent targets WCAG 2.2 AA for its critical flows and is designed to be fully operable without a pointer. This page covers what that means in practice, and the settings — yours and the product's — that change how it behaves.

  • All roles
RF-UG-15

Keyboard operation

Every control in RepoFluent is reachable and operable by keyboard, and focus is always visible — a cyan outline is used for nothing else, so if you see it, that is where you are.

Key Does
Tab from page load Reveals Skip to content, which jumps past the banner, header, and navigation straight into the page.
Ctrl K or ⌘ K Opens the command search dialog. It traps focus while open. Note that the search itself is not implemented.
Esc Closes the command search and returns focus to the button that opened it.
Back Closes an open source-context panel in a lesson rather than leaving the lesson. See Reading source context.

Where focus goes, and why it matters

  • On navigation, focus moves to the new page's main heading. You are never dropped at the top of the document to tab through the whole frame again.
  • On opening a dialog, focus moves inside it and is contained there; on closing, it returns to the control you used.
  • On opening source context, focus moves into the panel; on closing, it returns to the code reference you pressed.
  • On revealing more lesson blocks, focus moves to the first newly revealed block, so you resume reading in the right place.

Screen readers and announcements

RepoFluent announces things that happen without your involvement, which is most of what makes the upload flow usable non-visually.

Page changes
Announced as <Heading> page loaded after every navigation.
Curriculum operations
A live region named Curriculum operation status reports selection, upload, validation, success, and failure as they happen. You can follow an entire upload by listening.
The warning gate
A region named Warning acknowledgement status announces the change from Acknowledgement required to Warnings acknowledged.
Blocking issues
The issues table is announced as an alert when it contains blocking errors, and as an ordinary region when it contains only warnings.
Field errors
The upload field's error message is programmatically associated with the field, so it is read out with the field rather than being visual only.
Lesson progress
Showing 10 of 33 lesson blocks is announced as the count changes.
The development banner
Announced as a status, so you know you are in a non-production environment.

Visual content always has a text equivalent

  • Lesson diagrams are decorative and carry both a hidden text alternative and a visible caption. The caption carries the meaning.
  • The system map has an Accessible relationship companion — a table of every relationship with its direction and status, whose cells are buttons that select the same node the graph would. It is a full equivalent, not a summary, and it is always present rather than being a fallback.
  • Status is never colour alone. Every status pill carries a word as well as a colour, and severity in the issues table is a column, not a shade.

Reduced motion

If your operating system or browser is set to reduce motion, RepoFluent detects it and reduces every animation to effectively nothing. Two guarantees come with that.

  • State changes remain immediate. Nothing is only visible partway through a transition, and you never wait out an animation to see a result.
  • Nothing is hidden. Reducing motion removes movement, not information.

Your reduced-motion preference also takes precedence over the product's own visual enhancements, including the graphical system map.

Zoom and small windows

Zooming a browser to 200% is equivalent to halving the window width, so RepoFluent's responsive layout is what makes high zoom work.

  • Interactive controls stay visible and operable at high zoom — nothing is clipped or pushed off screen.
  • The page never scrolls sideways. Wide content such as tables and code excerpts scrolls inside its own frame instead.
  • Below tablet width the workspace explorer is dropped; on a phone-sized window navigation moves to the bottom and source context becomes a drawer.

Diagnostic and display options

RepoFluent accepts a few options in the address bar. They are intended for checking that fallbacks work, and they are genuinely useful if you are assessing the product's accessibility or explaining a problem to somebody.

Add to the address Effect
?theme=tenant Switches to the alternative tenant colour theme. Contrast and focus visibility are held to the same standard in both.
?gpu=off Turns off graphical acceleration for the system map. It falls back to the semantic view and reports the reason as policy-disabled.
?gpu=fail Simulates acceleration failing to start. The same fallback applies and reports initialization-failed.
?browser=unsupported Shows the browser compatibility guidance and the reduced-effects safe-access mode, so you can see what an unsupported browser gets.
?source=<number> On a lesson, opens a particular code reference's source context. This is added for you when you open one, which is what makes the address shareable.

This guide has its own two controls in its header — a theme toggle and a motion toggle — so you can see the same token system RepoFluent uses without opening the application.

Reporting an accessibility problem

Accessibility defects are treated as defects, not preferences. When you report one, include:

  • The page and the exact control.
  • Your browser, your assistive technology and its version, and your zoom level.
  • Whether reduced motion was on, and whether you had used any of the diagnostic options above.
  • The correlation identifier if the problem involved a failed action — see Identifiers.
