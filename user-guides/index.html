RepoFluent user guide

Learn a codebase the way it was built.

RepoFluent turns an organization's source code and documentation into courses, lessons, code tours, and assessments that stay tied to the code they describe. This guide takes you from opening the application for the first time through the advanced governance workflows, and it assumes you have never seen the product before.

What RepoFluent does

RepoFluent separates preparing content from delivering it. An AI agent analyses approved source material and produces a single JSON curriculum package. RepoFluent validates that package, a person reviews and approves it, and an approved version is published as learning that people can be assigned to.

The rule that shapes everything else is: agents prepare, humans approve. Nothing an agent produces reaches a learner until a reviewer has approved a specific, checksummed version of it and an administrator has published that version.

The curriculum lifecyclefive stages
UploadAuthor
ValidateRepoFluent
ReviewReviewer
PublishAdministrator
LearnLearner

Each stage leaves durable evidence — a checksum, an actor, and a timestamp — that the next stage is bound to. Retirement is a sixth state that withdraws a published version without deleting what people already learned from it.

Who does what

RepoFluent gives you a different set of controls depending on which role you hold. You will only ever see the actions your role allows at the current stage, which is why two people looking at the same curriculum can see different buttons.

Role What you do Start here
Learner Open the learning assigned to you, work through courses and lessons, and read the source code behind each explanation. My learning
Author Upload curriculum packages, read the validation receipt, and fix whatever the validator rejected. Uploading a package
Reviewer Preview a draft exactly as a learner would see it, acknowledge warnings, and approve or reject a version. Reviewing a draft
Administrator Publish an approved version, assign it to learners, compare versions, and retire content that is no longer accurate. Publishing and assigning
Auditor Read the complete lifecycle history for any curriculum without being able to change anything. Audit and support

One person can hold more than one role. See Roles and permissions for the full matrix of who can do what at each stage.

What this release does and does not do

RepoFluent is a working vertical slice, not a finished product. This guide documents only what actually works today, and it says so plainly wherever a control on screen is not yet connected to anything. Reading this section first will save you from hunting for features that are not there.

Working today

  • Uploading a curriculum package, asynchronous validation with a detailed receipt, and idempotent re-upload.
  • Learner-equivalent draft preview with answers withheld, exact warning acknowledgement, and immutable approve or reject decisions.
  • Publishing one immutable version, assigning it to a learner, and comparing or retiring published versions.
  • A learner dashboard, course outlines, eight kinds of lesson block, and source context bound to a specific commit.
  • A complete, ordered lifecycle audit trail readable by an auditor.
  • The published curriculum contract and the offline authoring kit, both retrievable with verified checksums.

Not in this release

These are visible but not functional

Answering or scoring a quiz or test; progress tracking of any kind (every progress figure you see is a placeholder); the Ctrl K search inside the application; analytics and reporting; managing users, groups, or tenants; and real authentication. Wherever one of these appears in the interface, this guide marks it rather than pretending it works.

The identities you sign in with are development personas, not real accounts. That is explained on Opening RepoFluent, and it is the single most important thing to understand before you start.
