Publishing and assigning

Publication is the moment content becomes real. It creates one immutable version, binds it to the checksum a reviewer approved, and makes it available to be assigned. Assignment is what actually puts it in front of somebody.

  • Administrator
RF-UG-11

Before you can publish

The Publish version button appears only when all of the following are true.

  • Your persona is Administrator.
  • The draft carries a recorded Approved review decision.
  • That approval matches the package's current checksum. An approval of different bytes does not count.

If the button is missing, one of those three is not satisfied. Check the Review decision evidence block: no block means no decision yet, and a Rejected pill means this version is never going to be publishable.

Publishing

  1. Press Publish version
    What you should see The status pill changes to Published and a Publication evidence block appears carrying an Active for assignment pill.
  2. Note the version identity

    The evidence block shows the new version's identifier. Copy it somewhere. There is no version list or picker anywhere in the product, so when you later want to compare versions you will have to paste this identifier in by hand — see Comparing versions.

Pressing publish twice is harmless: if the version already exists, RepoFluent returns the existing one rather than creating a second.

What the evidence block records

Version identity
The identifier of the published version you just created.
Package and package version
The author's stable identifier and declared version.
Published by
You. This is permanent.
Approved package checksum
The exact bytes that were approved and are now published. If this does not match what you expected, stop and investigate.
Availability policy
Whether the version is currently active for new assignments, or retained as history after retirement.
Publication event identifier
The audit event this action raised. It appears in the lifecycle history.

The four immutability guarantees

Publication displays four chips, and they are promises the product keeps rather than settings you chose.

Read-only content Source snapshot Assessments Protected answer policy retained

In plain terms: a published version's lessons, the commits its code references point at, and its assessment definitions can never change, and answer keys stay separated from learner-visible data for as long as the version exists. To change anything, an author publishes a new version.

This is why learning records stay meaningful

Because a version can never be edited, a record of somebody having learned from it always refers to specific, retrievable content. That property is what makes the audit trail worth anything.

Assigning it to a learner

Publication alone does not put content in front of anybody. Scroll to Assign published learning, which appears only while a version is published and active.

  1. Choose a learner

    The Learner menu has exactly one option: Maya Quinn · Learner. There is no user management in this release and no way to add a second learner.

  2. Decide required or optional

    Tick Required assignment for work that is expected, or leave it clear for enrichment. The learner sees this as a Required or Optional badge on their assignment card, and as REQ or OPTIONAL in their queue table.

  3. Press Assign learner
    What you should see The status region reads Assignment created. Switch to the Learner persona and it is on the My learning page immediately.

When assignment is refused

Refusal Reason
Not found The version has been retired. Retired versions keep existing assignments working but accept no new ones — that is the whole point of retirement. Publish a current version and assign that.
Learner does not exist Only the single seeded learner is recognized. You cannot invent a learner identifier.
No assignment form at all Either you are not an administrator, or the curriculum is not currently published.
Preview limitation — no assignment management

There is no list of existing assignments, no way to change one from required to optional after the fact, and no way to remove one. There are also no groups, no teams, no due dates, and no notifications. Assignment in this release is a single one-way action.

The rest of your job

Administrators own three further capabilities, each with its own page.

Advanced Comparing versions See what changed between two published versions and decide whether learners need to redo anything. Advanced Retiring a version Withdraw content that is no longer accurate without breaking learners who are already using it.

You can also read the full lifecycle history for any curriculum with Inspect lifecycle history, and retry a stalled validation on an author's behalf. Both are described on Audit and support and Uploading a package.

Preview limitation — no tenant administration

Despite the role name, there is no settings area, no user or group management, no roles editor, no retention configuration, no branding controls, and no analytics. The administrator persona in this release means precisely: publish, assign, compare, and retire.
